# Архитектура

## Слои

```
┌──────────────────────── гарнитура (ESP32-S3) ───────────────────────────┐
│  аудиотракт        арбитр звука      локальные умения      состояние    │
│  I2S mic → VAD     кто владеет       громкость, mute       лента, кнопки│
│  кадры 20 мс       микрофоном и      таймеры, будильники   переключатель│
│  I2S out ← речь    динамиком         таблица фраз роли     микрофона    │
└───────────────────────────────────┬─────────────────────────────────────┘
                                    │ бинарный WebSocket (WSS)
┌───────────────────────────────────┴─────────────────────────────────────┐
│                          AssistantService                                │
│  SpeakerGateway ── STT ── быстрый разбор / AgentRuntime ── TTS ── Opus    │
│                     │            инструменты            │                │
│                     └──────────── аудит и лимиты ───────┘                │
└───────────────────────────────────┬─────────────────────────────────────┘
                                    │
              FirmwareService (OTA, ключи) · IdentityService (привязка)
```

Гарнитура не содержит бизнес-логику платформы. Всё, что требует знания
пользователя и гонки, живёт на сервере. В устройстве — только то, что нужно,
когда сервера нет или он недоступен: громкость, mute, таймеры, встроенная
таблица фраз собственной сборки.

Слои в коде:

| Слой | Файлы | Ответственность |
|---|---|---|
| конфигурация | `firmware/src/config/AppConfig.h` | пины, лимиты, профиль платы, версия |
| протокол | `firmware/src/proto/Protocol.h` | типы кадров, сборка и разбор заголовка |
| аудио | `firmware/src/audio/AudioPipeline.*` | I2S вход и выход, преролл, VAD, уровень |
| связь | `firmware/src/net/SpeakerLink.*` | WSS, `HELLO`, `STATE`, приём речи и команд |
| сеть | `firmware/src/net/WifiLink.*` | подключение к сети, backoff |
| привязка | `firmware/src/net/BlePairing.*`, `PairingCrypto.*`, `DeviceConfig.*` | BLE-окно, ключ P-256, NVS |
| роль | `firmware/src/app/Role.h`, `LocalCommands.*` | вариант изделия и его таблица фраз |
| состояние | `firmware/src/app/Ui.*`, `LedLayout.h` | лента, кнопки, переключатель |
| умения | `firmware/src/app/Intents.*`, `Beeper.*` | громкость, mute, таймеры, сигналы |

## Арбитр звука

Один физический тракт обслуживает несколько источников, которые не должны
перебивать друг друга. Арбитр держит ровно одного владельца микрофона и одного
владельца динамика.

В гонке приоритеты отличаются от домашней колонки: важнее не «не перебить
разговор», а **не потерять указание агента на скорости**. Поэтому голос агента
стоит выше интеркома и служебных подсказок, а подсказки — выше фонового
разговора.

| Владелец | Приоритет | Микрофон | Динамик |
|---|---|---|---|
| Голос агента (ответ, команда) | 100 | свободен, если не запрошен | занят |
| Подсказки и предупреждения | 80 | свободен | занят |
| Интерком (разговор) | 60 | занят | занят |
| Автономные умения (громкость, mute, таймер) | 40 | по необходимости | занят на сигнал |
| Будильник / таймер | 90 | свободен | занят |

Правила:

* старший владелец **вытесняет** младшего: голос агента прерывает интерком,
  подсказка — фоновый разговор;
* младший не может вытеснить старшего, но может попросить
  (`preempt.request`);
* будильник вытесняет всё, кроме голоса агента: пропущенный сигнал в гонке
  хуже, чем оборванная фраза;
* после освобождения динамика возобновляется только то, что было приглушено
  (служебный фон), но не то, что было прервано (недосказанный ответ агента);
* микрофон и динамик принадлежат разным владельцам независимо: можно слушать
  пилота, пока агент молчит, и говорить, пока микрофон закрыт.

Состояние арбитра — **целевая архитектура**: в этой базе есть аудиотракт,
состояния ленты и команды `intercom.start` / `intercom.end`, а отдельного
модуля `AudioArbiter` в дереве ещё нет. Пока приоритеты обеспечиваются
последовательностью состояний в `main.cpp` и `Ui`.

## Микрофон и динамик

* Вход: I2S, 16 кГц, два канала; на распознавание идёт один (моно PCM16).
  Кадр — 20 мс (320 отсчётов), 640 байт.
* Преролл 0.9 с: обращение распознаётся с задержкой, начало фразы не должно
  потеряться.
* Конец фразы — 400 мс тишины; минимальная фраза — 250 мс.
* Выход: I2S-усилитель или внешний ЦАП, 16 кГц, речь агента и сигналы.
* PSRAM в рабочей сборке выключена: крупные буферы TLS в PSRAM ломают память
  Wi-Fi на этом ядре. Поэтому тракт живёт в SRAM, а все передачи идут через
  указатели и фиксированные пулы.

## Связь с сервером

Транспорт — один долгоживущий бинарный WebSocket на устройство:
`wss://<api>/api/assistant/speaker/stream`. Устройство сначала устанавливает
проверенный TLS-канал, затем отправляет `HELLO` первым бинарным сообщением.
Ключ и одноразовый токен запрещено передавать в URL или HTTP-заголовках.

```
гарнитура                              сервер
    │  HELLO {device, product, fw, hw,    │
    │         volume, muted, codec, rate,│  проверка ключа (хеш в базе)
    │         pub, key|token}             │
    ├─────────────────────────────────────►│  для токена: сверка pub
    │                                      │  с отпечатком привязки
    │  ◄──── HELLO_ACK {userId, voiceId,   │
    │         heartbeatSec, rulesVersion,  │
    │         serverTime}                  │
    │  ◄──── CODEC {opus, 16000, 20, 24000}│
    │                                      │
    │  ◄════ SAY / CMD ════════════════════│  дальше только кадры
    │  ────► MIC / VAD / STATE / EVENT     │
```

Схема — целевая. Сейчас `HELLO` объявляет `codec: "pcm16"`, микрофонный кадр
занимает 640 байт, а кадр `CODEC` прошивка не обрабатывает: переход на Opus —
следующий шаг ([`03-audio-protocol.md`](./03-audio-protocol.md)).

Сервер закрывает соединение, если корректный `HELLO` не пришёл за 5 секунд.
При отказе — `CONTROL {error:"unauthorized"}` и закрытие с кодом `4401`.

Два поля `HELLO` несут безопасность, а не диагностику:

* `pub` — открытый ключ устройства (несжатая точка P-256, 130 hex). При входе
  по одноразовому токену сервер сверяет `SHA-256(pub)` с отпечатком из записи
  привязки и только потом выдаёт `deviceKey`;
* `muted` — микрофон выключен. Пока он `true`, сервер не накапливает кадры
  `MIC` и не запускает распознавание. Прошивка в этом состоянии кадры не шлёт
  вовсе, но проверка на сервере остаётся: «микрофон выключен» — обещание
  пилоту, и оно не должно зависеть от версии прошивки на устройстве.

Команды, относящиеся к гарнитуре, приходят кадром `CMD`: `intercom.start`
переводит ленту в состояние разговора, `intercom.end` возвращает в простой.
Полный список кадров — в [`03-audio-protocol.md`](./03-audio-protocol.md).

## Отказоустойчивость

* Нет Wi-Fi — гарнитура работает автономно: громкость, mute, таймеры,
  встроенная таблица фраз (сейчас пустая для роли `Intercom`).
* Нет сервера — состояние `Offline`, лента показывает синюю искру.
* Канал связи потерян надолго — сторожевой таймер перезагружает устройство,
  чтобы не остаться в нерабочем состоянии до конца заезда.
* Повторное подключение — с backoff до 60 с, чтобы не долбить сервер при
  массовом отключении питания.
* Привязка и настройка — только по Bluetooth. Своего фронта у устройства нет:
  настройка живёт на сайте, Wi-Fi и привязка приезжают в зашифрованном кадре.
