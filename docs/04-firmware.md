# Прошивка

Проект — [`firmware/`](../firmware), PlatformIO, фреймворк Arduino. Один код
собирается в два изделия: гоночную гарнитуру и домашнюю колонку. База общая —
аудиотракт, связь, привязка; изделия, назначение и наборы команд разные.

```
firmware/
├── platformio.ini
├── partitions_speaker.csv        профиль классического ESP32
├── partitions_speaker_s3.csv     профиль ESP32-S3 N16R8
└── src/
    ├── main.cpp
    ├── config/AppConfig.h        пины, лимиты, профиль платы, версия
    ├── config/Secrets.example.h  шаблон локальных секретов
    ├── proto/Protocol.h          кадры: типы, сборка/разбор
    ├── audio/AudioPipeline.*     I2S вход/выход, преролл, VAD, уровень
    ├── net/DeviceConfig.*        NVS: Wi-Fi, ключ устройства, сервер
    ├── net/DeviceIdentity.h      id устройства из MAC
    ├── net/PairingCrypto.*       ключ P-256, расшифровка кадра привязки
    ├── net/BlePairing.*          GATT-сервис привязки и окно видимости
    ├── net/WifiLink.*            подключение к сети, backoff
    ├── net/SpeakerLink.*         WS-клиент, протокол, состояние связи
    ├── net/PublicRoots.h         публичные корни для стендовой сборки
    ├── app/Ui.*                  лента, кнопки, переключатель
    ├── app/LedLayout.h           раскладка ленты (уши, разделители, рот)
    ├── app/Role.h                вариант устройства: гарнитура или колонка
    ├── app/LocalCommands.*       встроенный офлайн-набор фраз этого варианта
    ├── app/Intents.*             локальные команды и таймеры без сервера
    ├── app/Beeper.*              тональные подтверждения
    └── app/Trace.*               трассировка
```

## Сборка

```bash
cd firmware
pio run -e esp32s3_intercom            # сборка гарнитуры
pio run -e esp32s3_intercom -t upload  # прошивка
pio device monitor -b 115200
```

`default_envs = esp32s3_intercom` — команда `pio run` без `-e` собирает именно
гарнитуру. Готовый образ для ручной прошивки — `DED_CORE_INTERCOM_S3.bin`; он
публикуется в разделе DIY на сайте платформы и собран из этой же сборки.

Перед первой сборкой скопируйте шаблон секретов:

```bash
cp src/config/Secrets.example.h src/config/Secrets.h
```

`Secrets.h` не публикуется: в нём доверенный CA платформы и закреплённый ключ
подписи привязки. В профиле `esp32s3_intercom` унаследован
`SPEAKER_BEEPER_SILENT=1` от базового `esp32s3`: пищалка молчит, пока флаг не
снят в собственной сборке. Без заполненного CA прошивка собирается, но **намеренно** не
поднимает TLS — это безопасный отказ, а не отключение проверки сертификата.

## Профили окружений

| env | Плата | Назначение |
|---|---|---|
| **`esp32s3_intercom`** | S3 N16R8 | **гоночная гарнитура, продуктовый профиль** |
| `esp32s3` | S3 N16R8 | база домашней колонки, продуктовый профиль колонки |
| `esp32s3_prod` | S3 N16R8 | серийная сборка колонки: требует flash-шифрование |
| `esp32s3_bench` | S3 N16R8 | стенд: окно привязки открывается при старте |
| `esp32s3_micdiag` | S3 N16R8 | диагностика микрофонов |
| `esp32s3_selftest` | S3 N16R8 | эталонный тон вместо микрофона |
| `esp32s3_ledtest` | S3 N16R8 | проверка пайки ленты |
| `esp32s3_psram` | S3 N16R8 | эксперимент с PSRAM, не для работы |
| `esp32da*` | ESP32-WROOM-DA | домашняя колонка на классическом ESP32 |

Сборки домашней колонки оставлены для совместимости базы и публикуются в
репозитории DED_CORE_SPEAKER. Гарнитура собирается только
`esp32s3_intercom`: в нём определён `SPEAKER_ROLE_INTERCOM`, а
`SPEAKER_ROLE_HOME` снят, поэтому домашние команды и имена-активаторы в образ не
попадают.

## Вариант устройства

Вариант задаётся при компиляции, а не приходит с сервера
(`src/app/Role.h`):

```cpp
enum class DeviceRole : uint8_t { Home, Intercom };
```

Причины две: автономные команды обязаны работать без сети, а таблица команд не
должна утекать в чужое изделие — иначе один образ можно было бы превратить в
другое устройство вместе с набором фраз.

Для роли `Intercom` таблица `localCommands()` пуста (`nullptr`, 0 записей), а
`isBuiltInWakeWord()` всегда возвращает `false`. Прикладные команды гарнитуры —
зажигание, карты, сценарии гонки — появятся отдельным слоем в её прошивке.

## Пины (ESP32-S3 N16R8)

| Сигнал | GPIO | Примечание |
|---|---|---|
| `MIC_BCLK` | 4 | I2S микрофон |
| `MIC_WS` | 5 | I2S микрофон |
| `MIC_SD` | 6 | I2S микрофон |
| `SPK_BCLK` | 15 | I2S выход |
| `SPK_LRC` | 16 | I2S выход |
| `SPK_DIN` | 17 | I2S выход |
| `I2C_SDA` | 8 | шина датчиков |
| `I2C_SCL` | 9 | шина датчиков |
| `BTN_ACTION` | 10 | действие: короткое нажатие, удержание 5 с — привязка |
| `BTN_VOL_UP` | 11 | громкость + |
| `BTN_VOL_DOWN` | 12 | громкость − |
| `SW_MUTE` | 13 | переключатель микрофона |
| `LED_STRIP` | 38 | внешняя лента, подписана RGB-OUT |
| `LED_STATUS` | 48 | встроенный WS2812 |
| `BUZZER` | 21 | пищалка (в `esp32s3_intercom` молчит: `SPEAKER_BEEPER_SILENT=1`) |
| `IR_TX` | 14 | объявлен, передача не реализована |
| `IR_RX` | 18 | объявлен, приём не реализован |

GPIO 26–32 заняты флешем, 33–37 — восьмибитной PSRAM, 19/20 — native USB,
43/44 — UART0, 0/3/45/46 — strapping. Всё выбранное выше свободно и не мешает
загрузке.

## Задачи FreeRTOS

| Задача | Ядро | Приоритет | Стек | Что делает |
|---|---|---|---|---|
| `mic` | 1 | 10 | 6144 | I2S DMA → кадр 20 мс → преролл → VAD |
| `spk` | 0 | 7 | 4096 | воспроизведение речи и сигналов, джиттер |
| `ws` | 0 | 5 | 8192 | WSS: `HELLO`, ping, приём кадров, реконнект |

Остальное — кнопки, лента, таймеры, сохранение настроек — крутится в главном
цикле Arduino, без отдельной задачи.

Аудио на одном ядре, сеть и декод — на другом: метки времени I2S не пересекаются
с сетевыми всплесками. Классический ESP32 без PSRAM не прощает копирования
больших буферов, поэтому передачи идут через указатели и фиксированные пулы.

## Состояния

```
BOOT → PAIRING (нет привязки, окно открыто) ──кадр принят──► перезагрузка → IDLE
IDLE ──обращение / кнопка──► LISTENING
LISTENING ──тишина 1.2 с──► THINKING
THINKING ──первый кадр SAY──► SPEAKING
SPEAKING ──SPEECH_END──► IDLE
SPEAKING ──"стоп" / barge_in──► IDLE
Любое ──потеря связи──► OFFLINE ──связь──► IDLE
Любое ──CMD intercom.incoming──► INTERCOM
```

Состояния ленты (`src/app/Ui.h`): `Boot`, `Unpaired`, `Pairing`, `Idle`,
`Listening`, `Thinking`, `Speaking`, `Offline`, `Error`, `Incoming`,
`Intercom`. Лента — 17 диодов: три уха слева, два разделителя, семь диодов
рта, два разделителя, три уха справа. Разделители погашены всегда, кроме
двухсекундной вспышки по обращению. В простое уши показывают уровень
микрофонов, рот дышит; в речи рот раскрывается по громкости голоса агента.

`muted` перекрывает любое состояние: лента красная, кадры `MIC` не уходят.

## NVS

| Namespace | Ключ | Тип | Смысл |
|---|---|---|---|
| `spk_cfg` | `wifi_ssid` / `wifi_pass` | string | сеть |
| `spk_cfg` | `api_base` | string | адрес платформы |
| `spk_cfg` | `device_key` | string | ключ из профиля |
| `spk_cfg` | `pair_token` | string | одноразовый токен привязки |
| `spk_cfg` | `name` / `room` | string | имя устройства и место |
| `spk_cfg` | `volume` | u8 | 0–100 |
| `spk_cfg` | `muted` | bool | переключатель и софт |
| `spk_cfg` | `rules_ver` | u32 | версия локальных правил |
| `spk_id` | `code` | string | код привязки с наклейки |

Ничего, что меняется чаще раза в минуту, в NVS не пишется: у ESP32 флеш
изнашивается, а `Preferences.put*` на каждом кадре убил бы её за месяцы.
Громкость пишется с задержкой после последнего изменения.

## Привязка по Bluetooth

Фронта на устройстве нет. Первый запуск без сети:

1. гарнитура генерирует пару P-256 и кладёт в NVS; при повторном включении
   ключ тот же;
2. длинное удержание кнопки действия (5 с) открывает окно BLE на 5 минут;
3. телефон или компьютер видит сервис `6b1f0001-9a3c-4e6d-8b1a-2c5d7e9f0a11`;
4. сайт читает `info` (id, открытый ключ, challenge, версия кадра), получает
   подписанный grant, шифрует настройки и пишет их в характеристику `pair`;
5. устройство расшифровывает кадр, проверяет подпись и отпечаток ключа,
   сохраняет настройки и перезагружается;
6. при первом WSS-подключении одноразовый токен меняется на `deviceKey`, после
   чего отпечаток ключа закрепляется.

Полный сценарий на сайте — `/speaker/pair`, механика и угрозы — в
[`05-pairing-security.md`](./05-pairing-security.md).

## Что проверяется на устройстве

| Проверка | Как |
|---|---|
| сборка без `Secrets.h` | `cp config/Secrets.example.h config/Secrets.h` и `pio run`: должна пройти |
| задержка обращения до первого звука | счётчик в прошивке печатает мс в лог |
| потери кадров | `seq` вниз, раз в 10 с в `STATE` |
| heap watermark | минимум `esp_get_free_heap_size()` за сессию, в `STATE` |
| реконнект | выдернуть Wi-Fi на 2 минуты, разговор должен восстановиться |
| привязка целиком | `/speaker/pair` → код с наклейки → кадр → перезагрузка → `HELLO_ACK` |
| подмена в эфире | подключиться чужим ключом: расшифровка должна отказать |
| язык ленты | каждое состояние видно с 3 м, mute перекрывает любое |
| крипто-путь | самопроверка на старте: ECDH → HKDF → AES-GCM |

## Что не реализовано

* акустическое распознавание фраз и wake word — таблица и маршрутизация есть,
  проверить команду голосом нельзя;
* прикладные команды гарнитуры: зажигание, карты, сценарии гонки;
* аппаратный AEC: PSRAM выключена, рабочая сборка полудуплексная;
* ИК-передача и приём;
* ESP-NOW;
* OTA-клиент: образ обновляется вручную через USB.

PSRAM выключена намеренно: замер на живой плате показал панику в приёмном пути
Wi-Fi при крупных буферах TLS в PSRAM на ядре Arduino 2.x / IDF 4.4. Включать её
можно только вместе с переходом на ядро Arduino 3.x и нагрузочным прогоном;
`esp32s3_psram` оставлен для этого эксперимента.
