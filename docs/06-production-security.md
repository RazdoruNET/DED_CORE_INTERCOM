# Серийная гарнитура: что обязательно сделать перед производством

Прототип хранит ключ устройства и пароль Wi-Fi в NVS открытым текстом. Пока у
человека нет физического доступа к плате, это не проблема; после первой поставки
— проблема: UART и чтение флеша дают ключ, а ключ — доступ к гарнитуре и её
настройкам. Здесь — минимальный набор требований, без которых партию выпускать
нельзя.

## Что защищаем

| Секрет | Где лежит | Цена утечки |
|---|---|---|
| ключ устройства (`deviceKey`) | NVS, `spk_cfg/device_key` | подключение к серверу от имени гарнитуры |
| пароль Wi-Fi | NVS, `spk_cfg/wifi_pass` | доступ в сеть пилота или бокса |
| код с наклейки | NVS, `spk_id/code` | возможность привязать гарнитуру к чужому аккаунту |
| ключ подписи grant | только на сервере (Vault) | в прошивку не попадает никогда |

## Обязательные меры

1. **Flash encryption (AES-XTS)** — включает шифрование всей флеш-памяти,
   включая NVS. Ключ шифрования хранится в eFuse и недоступен через UART.
2. **Secure boot v2** — загрузчик проверяет подпись приложения. Без него
   шифрование защищает только от чтения, но не от подмены прошивки.
3. **Запрет UART-загрузки в серии** (опционально, по модели угроз): после
   прожига eFuse `UART_DOWNLOAD_DIS` прошивка возможна только через OTA.
4. **Серийная сборка с `SPEAKER_REQUIRE_SECURE_FLASH`.** В базе этот флаг
   включён в `esp32s3_prod` — сборке домашней колонки. Для серийной гарнитуры
   его нужно включить в `esp32s3_intercom` (или завести отдельный
   `esp32s3_intercom_prod`): на старте проверяется
   `esp_flash_encryption_enabled()`, и без шифрования устройство не открывает
   привязку и не поднимает сеть. Это защита от «на плате забыли прожиг eFuse».
   Текущий `esp32s3_intercom` этой проверки не содержит — он макетный.
5. **Код привязки в NVS** — пишется при производстве в `spk_id/code`
   (каноническая форма: заглавные A-Z и 0-9). С прошитым кодом устройство
   принимает только кадр привязки версии 2: ключ шифрования настроек выводится
   с участием кода, поэтому подставное BLE-устройство без кода не прочитает
   пароль Wi-Fi. Без кода (кадр версии 1) этот риск остаётся — такие устройства
   допустимы только как макет.
6. **Сервер серии подписан CA платформы.** Прошивка по умолчанию доверяет
   только `SPEAKER_ROOT_CA_PEM`. Публичные корни (`SPEAKER_PUBLIC_ROOTS_PEM`)
   добавляются в цепочку лишь флагом сборки `SPEAKER_ALLOW_PUBLIC_ROOTS=1`:
   вместе с ними доверие расширяется до любого публичного CA, и тогда сервер
   может подделать тот, кто получит у него сертификат на наш домен — а в `HELLO`
   уходит ключ устройства. Флаг допустим только на стенде.
7. **Ключ подписи grant — не на рабочей машине.** `prod-signing.key` в `.dev/`
   каталоге разработчика — это ключ всей серии: с ним выпускают grant для любой
   гарнитуры. В git он не попадает (`.gitignore`), но попадает в резервные
   копии, облачную синхронизацию и архивы. Хранение — Vault (или HSM), доступ —
   по журналу, ротация — с перевыпуском grant. Каталог `.dev/` не должен лежать
   внутри синхронизируемой папки.

## Порядок производства

1. Собрать образ с `SPEAKER_REQUIRE_SECURE_FLASH` (для гарнитуры — серийный
   вариант `esp32s3_intercom`).
2. Записать код привязки и, если нужно, серийные данные в NVS до включения
   шифрования (после — только через OTA или шифрованный порт).
3. Прожечь eFuse: flash encryption + secure boot v2 (development mode на первой
   партии, production mode — после отладки). **Прожиг необратим.**
4. Первая загрузка в режиме разработки шифрует образ на месте; проверить в
   логе, что `[security]` не срабатывает, а `[crypto] код привязки прошит`.
5. Проверить, что чтение флеша внешним программатором даёт нечитаемый дамп, а
   привязка идёт кадром версии 2: сервер выдаёт `frameVersion = 2` в подписанном
   grant (устройство с кодом с наклейки принимает только её), `info.frame` — лишь
   подсказка для сайта.
6. Для каждой гарнитуры — запись в базе платформы: `deviceId`, хеш кода
   привязки, продукт. Отпечаток открытого ключа закрепится сам при первой
   привязке.
7. Проверить крепление и акустику конкретного корпуса: микрофон, динамик и
   переключатель должны оставаться доступными в шлеме, а лента — читаемой на
   солнце. Это не безопасность, но без этого партия не изделие.

## Что делать при утечке

* **Ключ устройства**: «Отвязать» или «Гарнитура украдена» в профиле —
  `report-stolen` блокирует устройство навсегда, `unbind` освобождает его для
  нового владельца. Ключ после этого не принимается.
* **Пароль Wi-Fi**: смена пароля в роутере; гарнитура перестаёт подключаться.
  После сброса кнопкой (10 с) NVS стирается, нужна новая привязка.
* **Код с наклейки**: гарнитуру нужно перепривязать с новым кодом, выданным при
  производстве; старый код в базе помечается недействительным.
* **Ключ подписи grant**: немедленная ротация, перевыпуск grant, аудит всех
  привязок за период компрометации.

## Что остаётся за рамками прошивки

* производственная база кодов и их печать (наклейка + QR `DED1:<id>:<code>`);
* хранение ключа подписи grant в Vault и ротация;
* проверка партии: сколько устройств реально ушло в продажу;
* защита от повтора записи голоса для команд зажигания и карт — это требование
  к прикладному слою, которого в базе ещё нет
  ([`07-roadmap.md`](./07-roadmap.md)).
